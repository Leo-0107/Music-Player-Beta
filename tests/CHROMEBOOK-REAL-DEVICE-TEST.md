# Chromebook / Chrome 実機テスト手順（PR #5専用）

## 目的と安全範囲

- 対象ソース：PR #5 の開発ブランチ `main15/pcm-worker-protocol-hardening` の内容。
- このテスト用ブランチはPR headを基点にした独立ブランチ。ここにある変更はテスト環境設定と手順書だけ。
- GitHub Pagesへのデプロイ、mainへのマージ、PR #5の更新は行わない。
- Codespacesの転送ポートは `private`。自分のGitHubアカウントで認証したブラウザから開く。
- テスト中に音が途切れる、異常なノイズが出る、操作不能になる場合は再生を停止する。音量は低めから始める。
- マイクモニターは初回試験では使わない。スピーカー使用時のハウリングを避けるため、マイク入力テストは別途計画する。

## A. Chromebookで開発版を起動する

1. ChromebookのChromeでGitHubにサインインする。
2. リポジトリ `Leo-0107/Music-Player-Beta` を開く。
3. ブランチを `test/chromebook-manual-audio-20261114` に切り替える。
4. **Code → Codespaces → Create codespace on test/chromebook-manual-audio-20261114** を選ぶ。
   - Codespacesが表示されない／利用できない場合は、ここで止めて知らせる。mainや公開サイトで代用しない。
   - 初回作成には数分かかることがある。
5. CodespacesのVS Code画面が開いたら、下部のTerminalを開き、次を1回実行する。

   ```bash
   python3 -m http.server 8000 --bind 0.0.0.0
   ```

6. 画面下部の **PORTS** タブを開き、ポート `8000` の **Open in Browser** を押す。
   - ポートが自動検出されない場合は、PORTSで「Add Port」から `8000` を追加する。
   - ポートのVisibilityは **Private** のままにする。
   - 開いたURLが `https://...-8000.app.github.dev` のようなCodespaces転送URLであることを確認する。
7. Music Player v7.4.59 が表示され、ローディングが終わることを確認する。
   - 画面が開かない、読み込みが終わらない場合は操作を進めず、画面の状態を知らせる。

## B. テスト音源の準備

1. この会話に添付された `chromebook_pcm_test_30s.wav` をChromebookの「ダウンロード」へ保存する。
2. アプリ画面でメニューを開き、「音楽 / ZIP / フォルダを追加」を押す。
3. ダウンロード内の `chromebook_pcm_test_30s.wav` を選ぶ。
4. 曲一覧にテスト音源が表示されることを確認する。
5. 曲を選択して再生する。初回は音量を小さくする。

## C. 基本PCM再生試験

各項目について「正常」「異常」「未実施」を記録する。

1. 再生開始後、音が聞こえ、再生時間が進む。
2. 一時停止すると音と再生時間が止まる。
3. 再開すると続きから再生する。
4. 再生バーを前後へ動かすと、その位置から再生する。
5. 曲の最後まで再生し、終了処理で画面が固まらない。
6. 30秒の音源を2〜3回再生し、繰り返しても音が出なくならない。

## D. 速度・ピッチ・EQ

1. 再生速度を一時的に `1.25x` にして、再生が速くなることを確認する。
2. 再生速度を `1.00x` に戻す。
3. ピッチを `+2` 半音にし、音の高さが変わることを確認する。
4. ピッチを `0` に戻す。
5. EQを小さく調整し、音が変化することを確認する。その後、EQを元の状態へ戻す。
6. 速度・ピッチ・EQを短い間隔で連続変更したとき、再生停止や大きな音飛びがないか確認する。

※大きなEQブーストは避ける。音量が急に大きくなったら停止する。

## E. Chromebookの出力先

1. Chromebook本体スピーカーで低音量のまま再生する。
2. 有線イヤホンが使える場合は接続し、ChromeOSのクイック設定から出力先を切り替えて再生する。
3. Bluetoothイヤホンを普段使っている場合のみ、ChromeOSのBluetooth設定で接続し、出力先を切り替えて再生する。
4. 出力先を切り替えた後も左右両方から音が出るか、再生が継続するか確認する。
5. Bluetooth接続が不安定なら無理に繰り返さず、結果を「未確認」または「異常」として記録する。

## F. 10〜15分の連続再生

- 30秒のテスト音源を繰り返し再生するか、手元の別の音源を使う。
- 5分、10分、可能なら15分時点で、音切れ・音飛び・停止・画面フリーズがないか確認する。
- 端末が熱くなる、動作が重くなる、異常音が出る場合は中止する。
- 1回の短いテストだけで長時間安定性が証明されたとは扱わない。

## G. 既存機能の回帰確認（安全な範囲）

- 通常の2Dステレオ再生：確認する。
- 3D／バイノーラル等：ヘッドホン使用時に低音量で短く確認してよい。異常があれば戻す。
- 音割れ防止：現在の設定状態を確認し、低音量で通常再生する。
- マイクモニター：この初回テストでは実行しない。
- YouTube／動画：今回のPCMローカル音声試験とは分け、必要なら別テストにする。

## H. 結果の報告

次の項目をコピーして、分かる範囲だけ記入して返信する。スクリーンショットはエラーや表示崩れがある場合だけでよい。

- Codespaces起動：成功／失敗／未実施
- ChromeOS / Chromeのバージョン：分かれば記入
- テスト音源読み込み：正常／異常
- 再生・一時停止・再開：正常／異常
- シーク：正常／異常
- 速度変更：正常／異常
- ピッチ変更：正常／異常
- EQ：正常／異常
- 本体スピーカー：正常／異常／未確認
- 有線イヤホン：正常／異常／未確認
- Bluetooth：正常／異常／未確認
- 10〜15分連続再生：正常／異常／未実施
- 気づいた音切れ・ノイズ・遅延・画面表示：自由記入

## 注意

このテストはChromebook上のChromeで実際の出力デバイスを使うため、headless Chromiumより実機に近い確認になる。ただし、Codespacesはアプリの配信元サーバーであり、音声処理と出力はChromebook側のChromeで行われる。テスト結果は端末・ChromeOS・接続機器の組み合わせに依存する。

この手順書はテスト準備であり、実機試験の合格を意味しない。
